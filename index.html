Problem → Solution

Android and Windows never tell you what's watching.

iOS has had camera/mic indicator dots for years. Android and Windows still leave sensor access invisible unless you dig through settings after the fact. YPI puts that same always-visible signal on both platforms, plus a record of it you can actually go back and check.

Security

On-device monitoring, encrypted at rest

YPI watches OS-level sensor callbacks and Android's NetworkCallback API to detect access — it doesn't need special access to app internals to know a sensor turned on.

Monitored: Camera · Microphone · Network · Bluetooth · Location Rendering: Emoji-badge overlay — the canonical, established approach after iteration; chosen for instant legibility over icon sets Storage: Encrypted session logs, on-device only, no cloud sync

FAQ

Common questions

Does the overlay slow down my device?

The overlay reads OS callback events rather than polling, so it's idle until a sensor actually activates.

Why emoji badges instead of icons?

After iteration, emoji rendering was established as the more legible, lower-maintenance approach across both light and dark backgrounds.

Is the Windows app the same codebase?

No — it's a separate WPF (.NET 8) app built in parallel, covering the same six sensor categories using native Windows APIs.
